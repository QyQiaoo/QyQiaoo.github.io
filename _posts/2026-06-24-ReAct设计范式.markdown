# ReAct 设计范式

> **ReAct** 是一种能让大模型（LLM）像人一样“边想边做”的智能体设计范式，其通过将推理（Reasoning）与行动（Acting）紧密结合，让模型不仅能“思考”问题，还能主动调用外部工具获取信息，并根据反馈动态调整计划，从而解决仅靠内部知识无法完成的复杂任务。

---
## 一、 为何需要 ReAct？

在 ReAct 出现前，提升 LLM 复杂任务能力主要有两种方法，但各有缺陷：
- **思维链（Chain-of-Thought, CoT）**：模型通过一步步推理来解决问题。但它完全依赖模型内部的静态知识，无法获取新信息，容易产生“幻觉”或事实错误。
- **行动-only（Act-Only）**：模型直接输出与外部环境交互的动作。但缺乏推理规划，遇到错误或意外情况时难以调整策略。

ReAct 正是为了结合两者优点而诞生，由普林斯顿大学和谷歌研究院的研究人员在2022年提出。

## 二、 核心机制：思考-行动-观察（TAO）循环

ReAct 的核心是 **“思考（Thought）— 行动（Action）— 观察（Observation）”** 的迭代循环。它像人类解决问题一样，在“思考”和“动手”之间交替进行。

| 步骤 | 含义 | 作用 |
| :--- | :--- | :--- |
| **思考 (Thought)** | 模型的内部推理过程 | 分析当前状态、拆解任务、制定或调整计划。 |
| **行动 (Action)** | 模型执行的具体外部操作 | 调用工具（如搜索引擎、计算器、API）与环境交互，获取信息或改变状态。 |
| **观察 (Observation)** | 执行行动后从环境获得的反馈 | 将新信息（如搜索结果）提供给模型，用于下一步的思考。 |

这个循环会持续进行，直到模型认为自己掌握了足够信息，可以给出最终答案为止。

## 三、 核心优势

ReAct 的设计带来了显著优势：
- **可解释性与可信度**：所有推理和行动步骤都被记录，形成透明的决策轨迹。
- **动态规划与适应性**：能够根据环境反馈动态调整计划，处理突发状况。
- **突破知识局限**：能调用外部工具获取实时信息，克服了模型固有知识的局限性。
- **任务分解能力**：通过逐步推理，将复杂任务拆解为可执行的子任务。

## 四、 应用场景

ReAct 适用于多种复杂场景：

- **问答与信息检索**：处理需要多步、实时信息的复杂问答。
- **自动化决策**：用于自动客服、旅行规划等。
- **数据分析与计算**：结合数据库查询和计算工具进行数据分析。
- **科研与工程**：用于自动化特征工程、代码生成等。

## 五️、 局限性与挑战

ReAct 也并非完美无缺：

- **推理成本与延迟**：多轮“思考-行动”循环会带来更高的计算成本和响应延迟。
- **错误累积与循环**：前期的错误可能被放大，也可能陷入无效的“行动-观察”循环。
- **提示工程的敏感性**：其效果高度依赖提示词（Prompt）的设计。ReAct对提示词的依赖，本质上不是依赖“某一句神奇的咒语”，而是依赖提示词建立的一套完整的“行为规则和格式约束系统”。
- **安全与对齐风险**：赋予模型调用外部工具的能力可能带来安全风险。

## 六、 关键变体与扩展

为克服局限，研究者提出了多种改进方案：

- **Reflexion**：在 ReAct 基础上增加“自我反思”机制，让模型从错误中学习。评估 + 反思 + 记忆：任务失败后，让模型自我分析错误原因，生成文本形式的“经验教训”存入长期记忆，指导未来的尝试
- **Focused ReAct**：通过“重述”和“早停”机制，防止模型在推理中失去焦点或陷入循环。重述 + 早停：每一步推理都强制把原始问题再强调一遍，让模型“不忘初心”；同时监控行动，一旦发现重复就立即喊停，强制输出答案
- **Co-ReAct**：引入“规则”（Rubrics）作为逐步指导，提升行动选择的准确性。规则（Rubrics）引导：引入一个专门训练的“规则生成器”，在每一步决策时，都生成一条明确的、分步骤的指导规则（Rubric），告诉Agent当前应该重点找什么、怎么推理

## 七、 总结
总的来说，ReAct 通过将推理与行动结合，为构建能够解决复杂任务的智能体提供了一个强大而优雅的框架。它推动了 AI 从被动的信息提供者向主动的问题解决者演进。
