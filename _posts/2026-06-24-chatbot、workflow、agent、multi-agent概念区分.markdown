# Chatbot、Workflow、Agent、Multi-Agent 感念区分

> 这四个概念代表AI自动化程度的**四个递进层级**：从"只会说"到"自动化流水线"，再到"拥有大脑和手"，最后升级为"团队协作"。

## 一、 核心区别

- **Chatbot（聊天机器人）**：只会基于已有知识对话，不会主动做事。
- **Workflow（工作流）**：**自动化流水线**。按照你写死的剧本，一步步严格执行。
- **Agent（智能体）**：**大脑 + 手**。自己设定目标、自己拆解步骤、自己调用工具干活。
- **Multi-Agent（多智能体）**：**团队会议**。多个"大脑"分工协作、辩论、互相检查。

## 二、技术视角

### 1、Chatbot（聊天机器人）

- **核心逻辑**：**"检索 + 生成"**。输入提示词 → 调大模型API → 输出结果。
- **特点**：**无状态（或浅状态）**、**无工具调用权**。它只能"说"，不能"做"。比如你让它订机票，它只会告诉你订票步骤，但不会真的去操作购票系统。
- **适用场景**：客服问答、知识百科、翻译、头脑风暴。

### 2、 Workflow（工作流）

- **核心逻辑**：**"硬编码的逻辑"**。开发者用代码把流程写死：`如果A则B，否则C；然后执行D；最后汇总E`。
- **特点**：**确定性**。同样的输入，100%产出同样的流程。大模型只是流程中的"一个计算节点"（比如只负责提取关键词，后面的路由和调用API都由代码控制）。
- **适用场景**：简历自动筛选（提取字段存库）、日报自动生成（拉数据→套模板→发邮件）、RPA（机器人流程自动化）。

### 3、 Agent（智能体）

- **核心逻辑**：**"大模型作为推理引擎（大脑）"**。它遵循 **ReAct（推理+行动）** 模式：思考 → 调用工具（查天气/订票/写代码） → 观察结果 → 再思考 → 直到完成目标。
- **关键区别**：**自主决策权**。给Agent一个目标（"帮我订一张去上海的票"），它会自己决定先查航班还是先查高铁，自己决定用哪个API，如果没票了它会自己改签候补。
- **适用场景**：自动编程（Devin）、个人旅行规划师、复杂数据分析和可视化。

### 4、 Multi-Agent（多智能体）

- **核心逻辑**：**"SOP（标准作业程序）的社会化模拟"**。将不同角色（规划师、工程师、测试员、CEO）赋予不同的Agent，让他们通过消息传递进行协作或博弈。
- **关键区别**：**涌现智能**。单个Agent容易陷入"思维茧房"，而多Agent通过辩论（如"双Agent辩论机制"）能显著提升事实准确性。
- **适用场景**：模拟软件开发团队（MetaGPT）、复杂科研实验设计、多部门预算协商。


## 三、 直观对比表格

| 维度 | Chatbot | Workflow | Agent | Multi-Agent |
| :--- | :--- | :--- | :--- | :--- |
| **决策权** | 零 | 完全在开发者手中 | **在模型手中** | 在模型 + 协作协议手中 |
| **工具调用** | 不能 | 由代码硬编码调用 | **自主决定**何时、调哪个 | 自主决定 + 分工调用 |
| **处理复杂任务** | 极差（只输出文本） | 优秀（依赖预先设计） | 优秀（自主探索） | **极强**（并行 + 纠错） |
| **成本** | 低 | 中（开发成本高） | 中高（循环Token消耗大） | 高（多轮对话 + 多角色） |
| **可控性** | 高 | **极高（稳定）** | 低（不可控性强） | 中（通过角色约束） |


## 四、 落地建议

| 需求场景 | 推荐方案 | 理由 |
| :--- | :--- | :--- |
| **要"稳"**（金融交易、医疗数据处理） | **Workflow** | Agent的幻觉在这种场景下是灾难 |
| **要"准"**（法律咨询、客服） | **RAG增强的Chatbot** | 基于固定知识库，输出可控 |
| **要"灵活"**（市场调研、内容创作、需查最新资料） | **Agent** | 自主探索和工具调用能力突出 |
| **任务太大太复杂**（做APP、写一本书） | **Multi-Agent** | 并行分工 + 相互纠错，但需定义好角色边界，否则会陷入无限循环聊天 |
